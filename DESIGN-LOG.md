# DESIGN-LOG: HolyC and TempleOS (new site)

**Run.** DADA, Adaptive mode, Full run type (the repository was empty: no commits, so there was nothing to preserve and no legacy branch to save), **bounded to one panel round**. The landing is designed as a poster from the start, applying the lesson of the two earlier "C" grades (Prometheus Stack, Learn Bash): a first screen that is correct but forgettable is a miss. Look: a new design pack, `vga-sixteen` (SolutionsAsService/dada-changes, `skills/dada/designpacks/`).

## R0. Brief and constraints
Brief: a site covering HolyC examples, TempleOS and Terry A. Davis, from scratch. Constraints found while working:
- **No real HolyC compiler could be run.** A community compiler (holyc-lang, BSD-style licence) was cloned to see whether examples could be run on a real implementation; building third-party code was blocked by the environment's safety check, and was not worked around. The site therefore does not claim its outputs come from a real HolyC compiler.
- **The content is from general knowledge.** There is no web access here and nothing was checked against the TempleOS documentation or Davis's own writing. This is a high-risk subject (a real person with serious mental illness, a religious claim, offensive statements), so honesty about confidence is part of the design.

## Decisions
**D1 Every example is run, by an interpreter written for the site.** `holyc-core.js` is a small interpreter for a subset of HolyC (types with wrap-around, string-literal print statements, functions with default and skipped arguments, calls without parentheses, C control flow, arrays of numbers, simple classes, #define). The build refuses to run if an example has no recorded output. Every output on the site is labelled "from this site's interpreter", never "from TempleOS". D2 **The interpreter is checked against C.** `scripts/check-holyc.js` runs 29 programs, 26 of them compared with equivalent C compiled with gcc; the first run caught a real divergence (printf rounds exact ties to even, JavaScript rounds them up: `%.0f` of 2.5 is 2) and three missing refusals, all fixed. It also refuses 16 bad programs with clear messages. This verifies the interpreter against C semantics, not against TempleOS, and says so. D3 **Every fact carries a mark:** Firm, Reported or Uncertain, as a rule style plus a word, never colour alone. D4 **Every colour on the site is one of TempleOS's 16** (the standard VGA palette); the build refuses to run if `styles.css` uses any other colour, a gradient or transparency. D5 **The landing is the screen:** a bezeled 640x480-style blue screen holding a pixel-art `HolyC` logo (drawn from bitmaps, one palette colour per letter), a real program and its real output, and the full 16-colour palette strip with names and numbers. D6 **Dark by default, like the system; a light page when the system asks.** D7 **A careful page about a person:** the Terry A. Davis page states how it is written, mentions his illness and his offensive statements without repeating them or treating them as entertainment, and sticks to the record. D8 **A playground** runs the same interpreter in the browser, with partial output and line-numbered errors, and the page lists what it does not support.

## Measured so far
Mobile Floor 12 of 12 on all six pages at 360, 390 and 430px. A contrast walk of 199 distinct text and background pairs across the six pages, in both colour schemes, found none under threshold, after fixing two real failures (a dark-grey mark on light grey; a muted "(no output)" on black in the light scheme). The palette rule: 16 colour values in `styles.css`, all from the 16. In a real browser the playground runs a valid program, shows partial output and a line-numbered error for a runtime fault, stops an infinite loop, refuses a pointer and an unknown character, runs with Ctrl+Enter, and every lesson page is complete without JavaScript.

## Measured (after the fixes)
- Interpreter checker: 36 programs (31 compared with gcc-compiled C), 27 bad programs refused with clear messages, 400 fuzzed programs that never threw, partial output and line numbers kept.
- A real-browser run of 10 new programs in the playground: a string `#define` runs; `print(`, `int`, a wrong-case variable, a redeclaration, a multi-token `#define`, a 30-digit literal and a 100,000-iteration array allocation are each refused with a plain message; an output flood stops at the cap; `%.2f` of 1e21 prints in full.
- Mobile Floor 12 of 12 on all six pages; a contrast walk of 214 distinct text and background pairs in both colour schemes found none under threshold; the build confirms the stylesheet still uses only the 16 colours.

S1 not met (no R2). S2 not met (round 1's changes were judged by measurement and a browser check, not re-judged by the panel). **Reported as incomplete under the one-round bound.**

## Open
- All facts are from general knowledge and none has been checked against a source; the Wikipedia articles on the resources page are the place to check. "Firm" means consistent in the author's memory, not verified.
- Outputs come from this site's interpreter, which is checked against C (arithmetic, wrap-around, division, shifts, formatting) but not against TempleOS. A real HolyC compiler could not be built here (the environment blocked building third-party code).
- The interpreter uses C operator precedence, prints `$` literally, and does not handle signed against unsigned comparison or `%d` of a U64 above 2^63; these are documented on the playground page.
- Not shown on a real phone (the Run button with the keyboard open, iOS zoom on the textarea).
- No inclusion seat.
