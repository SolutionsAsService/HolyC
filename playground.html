What it supports

  • Types U0, Bool, I8 to I64, U8 to U64 and F64, with wrap-around at each size.
  • String statements and Print with %d %u %x %X %c %s %f (use %.2f and the like for floats) and %%.
  • Functions with default and skipped arguments, calls without parentheses, recursion.
  • if, else, for, while, do while, switch, break, continue, return.
  • Arrays of numbers, U8 * strings, simple classes, #define, built-ins Print, PutChars, StrLen, Sqrt, Sin, Cos, Abs, Min, Max.

What it does not

  • Pointers other than U8 * strings, memory allocation, asm, try and catch, goto, the file system, graphics, sound and the rest of TempleOS.
  • Arrays of characters, two-dimensional arrays, array members in classes, function-like #define, and a #define with more than one token.
  • HolyC's operator-precedence differences: it uses C precedence, so avoid mixing bitwise operators with comparisons.
  • The $ document-format escape: a dollar sign prints as it is.
  • Large unsigned values: use %u to print a U64 above 9 quintillion, and avoid comparing signed with unsigned.
  • Anything that depends on TempleOS itself. For that you need the real system.

Limits: programs of up to 6,000 characters, about 3 million steps, 8,000 characters of output, 1,000,000 array cells in total, and recursion 400 deep.

The interpreter is checked against real C programs compiled with gcc for arithmetic and formatting (see scripts/check-holyc.js), not against TempleOS.
