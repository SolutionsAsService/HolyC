The language

HolyC from scratch

The programming language of TempleOS: C-like, with a built-in compiler, no main function, and a shell that is the language itself.

Hello, world

In HolyC a string literal on its own is a statement, and it prints. There is no main function to write and no include: code typed at the prompt runs as soon as you press Enter, because in TempleOS the language and the shell are the same thing.

A program is just a list of statements, run from the top. A function defined earlier can be called by a later line.

Types

The integer types say their size: I8, I16, I32 and I64 are signed, U8, U16, U32 and U64 are unsigned, and the number is the bits. F64 is a 64-bit floating-point number, Bool is true or false, and U0 means no value, the type of a function that returns nothing. There are no int, char or float keywords.

I64 is the type to reach for by default. A character is a U8; a constant like 'A' is its code.

Functions

A function is declared with its return type first: U0 for none. A function with no arguments can be called without parentheses, which is why a lone name like Greet; on a line runs it. Arguments can have default values, and a call can leave an argument out by keeping the comma.

Define a function before the line that calls it.

Loops and choices

The control statements are the ones from C: if and else, for, while, do while, switch with case and default, break and continue. A switch falls through from one case to the next unless you break.

Strings and arrays

A string is a pointer to characters, written U8 *. Indexing gives the character code, and StrLen counts. A fixed array is declared with its size and can be filled in braces.

Classes

A class groups named fields, like a C struct, and a variable of that class holds all of them. Fields are reached with a dot.

Numbers wrap around

A fixed-size integer has no room beyond its largest value: add one and it wraps to the smallest, with no error. This is what a 64-bit machine does, and HolyC does not hide it.

The same happens to a U8 at 255 and an I64 at 9,223,372,036,854,775,807.

How it differs from C

HolyC looks like C. These are the differences that matter first, each with a mark for how sure we are.

The marks:FirmReportedUncertainReported does not mean doubted. None of these facts has a source attached yet; the Wikipedia articles on the resources page are where to check them.

  • No main, no setup

    Statements at the top level run immediately, in order. The compiler is part of the operating system, so the prompt, scripts and programs all use one language.

    Firm

  • A string statement prints

    A bare string literal is a statement that prints it; extra values after commas fill the % codes. Print(...) does the same explicitly.

    Firm

  • Sized type names

    U0, I8 to I64, U8 to U64 and F64 replace void, char, int, long and double.

    Firm

  • Calls without parentheses

    A function that needs no arguments can be called by its name alone.

    Firm

  • Default and skipped arguments

    A parameter can have a default, and a call can leave an argument out by keeping its comma.

    Firm

  • Inline assembly and the compiler as a service

    asm blocks sit inside HolyC code, and code can be compiled and run at run time because the compiler is always present.

    Firm

  • Classes with inheritance

    class groups fields like a struct and can extend another class.

    Reported

  • A richer switch

    switch can contain start and end sections for sub-cases.

    Reported

  • Exceptions

    try, catch and throw exist; a thrown value is a short constant.

    Reported

  • $ is special in strings

    In text shown by the system, a dollar sign begins a document-format command, so a literal dollar is written twice.

    Reported

  • Operator precedence

    Some operators, notably the bitwise ones against the comparisons, bind in a different order from C. This site's interpreter uses C precedence, so avoid mixing them.

    Uncertain
